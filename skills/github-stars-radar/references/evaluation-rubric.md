# Repository 評分量表

## 原則

只使用 repository metadata、README、LICENSE 與可驗證的一手資料。先寫一句話定位與解決問題，再逐項評分。缺乏證據時給中低分並標示未確認，不以 Stars 數直接代替品質。

## 100 分制

| 面向 | 配分 | 高分證據 |
|---|---:|---|
| 現有系統契合度 | 30 | 可直接增強 Second Brain、Evo_PRISM、研究、程式開發或 AI 工作流，且責任邊界清楚 |
| 實際問題價值 | 20 | 解決已存在且頻繁的痛點，可衡量改善 |
| 成熟度與維護 | 15 | 近期維護、版本清楚、issue 管理合理、非封存 |
| 差異化 | 10 | 不只是現有工具的重複包裝，具有可借鑑設計 |
| 文件與可採用性 | 10 | README、安裝邊界、設定與範例清楚 |
| 授權與安全 | 15 | 授權明確、依賴與資料流透明、無明顯高風險行為 |

逐項給整數分並列一句證據，總和必須等於各項加總。

## 分級

- `75–100`：`deep-review`。自動深入閱讀一手內容並提出整合邊界、PoC 與風險。
- `50–74`：`watch`。保留完整候選卡，列入週報，不自動深入。
- `0–49`：`record-only`。保留基本解釋、metadata 與低分理由，不主動通知。

## 深度分析內容

對 `deep-review` 項目補充：

1. 核心架構與真正差異化設計。
2. 與現有系統的正確責任邊界。
3. 可借鑑而不必整套導入的原則。
4. 安全、授權、維護與 vendor lock-in 風險。
5. 一個隔離、可回復、不可觸及敏感資料的 PoC。
6. 明確結論：立即試用、隔離 PoC、持續觀察或不採用。

不得因高分而安裝或執行 repository。
