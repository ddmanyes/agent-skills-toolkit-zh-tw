# 教學與格式規格

以領域專家維持學術嚴謹，以教學設計師串起動機、直覺、實作與適用的形式化解釋。不能為了容易讀而省略複雜定義、替代模型、公式或 C++／Java／Python 等對照範例。

## 七個教學層次

1. **章節核心**：用 abstract callout 說明本章解決甚麼問題。
2. **背景與動機**：還原來源場景與可信的人物／年代；補充資訊附來源，未出現的歷史不硬加。
3. **術語對照**：必要時以表格連結正式名稱、中文及實務用語，例如 Relation／Table。
4. **概念解析**：保留全名、正式及非正式定義、公式，按概念需要加入直覺、比喻、反例；比喻要說明界限。
5. **案例與視覺邏輯**：還原所有來源案例的業務規則、資料表、程式碼、實體屬性、關係基數及參與約束。從圖示推導的隱含規則需標成推論並檢查。
6. **設計決策與雷區**：保留 Think／Important／Design Issue 標記，以 important、warning、danger 或 tip callout 說明理由。「考點」表示適合自我檢測的知識點，不保證考試出題。
7. **自我檢測與複習**：完整章節預設五題，覆蓋定義、比較、實作、陷阱與設計選擇；短章依實質內容減量，或採用使用者指定數量。每題附可核對的答案與解釋。

## 視覺形式按資訊需要選用

| 資訊 | 適合的形式 |
| --- | --- |
| ER 關係 | Mermaid erDiagram |
| 流程／演算法 | flowchart |
| 樹狀屬性 | graph TD |
| 概念差異 | Markdown 表格 |
| 程式碼／SQL | 對應語言 fenced code block |
| 分類與層次 | 清楚的標題與清單 |

圖表應增加理解；純文字章節不為滿足數量而硬插 Mermaid。保留程式碼語言、邏輯與輸出例，不能只翻譯註解而漏掉實作。

## 可調整的章節範本

```markdown
# [課程／模組]：[中文標題] ([英文標題])

> [!abstract] 章節核心
> 本章問題與來源頁碼。

## 1. 為甚麼要學這個？
## 2. 核心術語
## 3. 概念與形式化定義
## 4. 案例、程式碼與視覺說明
## 5. 設計決策與易錯處
## 6. 自我檢測
**Q：問題**
> A：答案與理由。

> [!tip] 複習建議
> 與前後章的連結。
```

交付前比對來源的每項定義、範例、數據及限制；將未能確認的資訊明確標示，保持自然、親切而精確的說明。
