# 圖表類型選擇

| 使用者問題 | 建議類型 | 主要布局 |
|---|---|---|
| 系統由哪些部分組成？ | Architecture | 邊界＋服務＋依賴 |
| 工作怎麼一步步完成？ | Flowchart／Process | 單向主線＋決策分支 |
| 資料從哪裡來、如何轉換？ | Data flow | 來源 → 處理 → 儲存／消費 |
| 誰在什麼時候和誰互動？ | Sequence | 參與者欄＋時間軸 |
| 事件如何隨時間變化？ | Timeline | 時間主軸＋里程碑 |
| 想要極簡節點與線路？ | Dots／Signal flow | 圓點主線＋少量支線 |
| 想比較選項或象限？ | Matrix／Quadrant | 一致維度與軸標籤 |

## Architecture

- 先畫外部邊界與信任區，再畫內部節點。
- 依賴線應能說明方向；雙向關係必須有明確理由。
- 相同層級的節點使用相同尺寸與樣式。

## Flowchart／Process

- 起點與終點必須可辨識。
- 決策節點的每個出口都要有條件標籤。
- 回圈線靠外圍走，避免切穿主流程。

## Data flow

- 區分控制流與資料流；必要時使用不同線色或線型。
- 節點標籤優先使用動詞＋受詞，例如「驗證輸入」。
- 儲存層、處理層與消費端應在空間上分開。

## Sequence／Timeline

- 時間只能朝一個方向前進。
- 省略不影響結論的互動，避免把 log 全部搬進圖表。
- 強調關鍵轉折、失敗路徑或等待時間。

## Dots／Signal flow

- 圓點代表能力或狀態，線代表交接。
- 主線承載核心敘事；支線只保留必要影響。
- 節點標籤上下交錯，長名稱放在較寬間距處。
- 焦點節點可使用實心色與柔和 halo，但不得造成視覺噪音。
