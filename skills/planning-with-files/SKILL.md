# 檔案規劃系統
沿用專案既有計畫與紀錄慣例。先讀取足以判斷任務與現有檔案的內容，再決定需要哪些紀錄。

## 紀錄用途
- task_plan.md：目標、授權範圍、階段、可驗收任務與下一步。已有 IMPLEMENTATION_PLAN.md 時使用它，不維護兩份相同計畫。
- findings.md：可重用的發現、來源、決策理由與陷阱。
- progress.md：每個階段的實際變更、驗證結果、失敗與恢復點。

只建立本任務需要且尚無對應用途的檔案。在階段完成、重要決策改變、遇到阻礙或需要交接時更新；連續查閱資料不要求固定次數的寫入。

## 執行與驗收
1. 以現有資訊定義範圍和完成條件；缺少的事實先查，只有必要決策才問。
2. 在新階段或恢復會話時核對目前計畫及最新結果。
3. 驗證成功才勾選完成。記錄有助復原的失敗原因及已試方法，避免抄入秘密或大量無關 log。
4. 結束時確認計畫與實際成果一致、未完成工作有原因及下一步，用繁體中文回報實質進度，不反覆展示整份計畫。
