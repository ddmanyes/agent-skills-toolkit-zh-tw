# REA 調查

REA 上游是 [morluto/rea](https://github.com/morluto/rea)。它提供 MCP／CLI；skill 只提供流程，不能代替工具連線。使用當前可發現的工具 schema；不要從歷史筆記猜工具名或參數。

## 準備

確認目標的實際路徑、版本、hash，以及使用者指定的研究問題。只將授權檔案副本放入本機隔離工作區。讀取對應的 REA 上游指引；記錄本次 REA 與分析引擎版本。原始碼已能回答時不必啟動 REA。

MCP 缺席時，可在已有安裝與授權下使用 CLI；否則完成不依賴 REA 的來源研究，明示工具未連接。skill 執行本身不自動授權安裝 REA、Hopper、Ghidra 或修改全域 agent 設定。

## 執行界線

先使用靜態檢查。需要啟動應用、attach 程序或擷取網路時，核對既有授權是否涵蓋確切目標與操作；未涵蓋則先呈現具體操作及預期產物，取得授權後再執行。

REA 在本機分析不代表結果只留本機：回傳內容可能進入 agent 的模型上下文。不要把秘密或未授權私人資料納入工具結果、日誌、SB 或提示。

錯誤或不支援的格式：保留原始診斷，標 UNKNOWN；不要無限換工具或擴大到其他程序。只在有明確可修復原因時重試，另記 retry_of。來源與目標不一致時停止依賴該證據的推論。

## 從觀察到實作

將觀察整理為輸入／輸出契約及邊界案例；反編譯偽碼不視為完整原始碼。重建行為須用固定測試向量比對；相似畫面不證明演算法相同。檢查所採程式碼、模型權重與資料各自的授權，不能由 REA 的 MIT 授權推定目標產物可再散布。

保留 source receipt、觀察、假說、測試與結果的關聯。若使用者要求 clean-room 開發，僅有不同 agent 名稱不足以隔離資料，須另定真正的環境與存取邊界。
