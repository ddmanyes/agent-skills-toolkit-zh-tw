# 超級能力：設計腦力激盪 (Design Brainstorming)

在動手寫程式之前，像面試官一樣「拷問 (grill)」使用者的每一個決策，直到雙方達成**共同理解 (shared understanding)** 為止。目標不是快速產出方案，而是把模糊的意圖逼成明確的規格。

## 核心規則 (Core Rules)

1. **硬性門檻 (HARD-GATE)**：在方案獲得使用者「正式批准」前，禁止任何實作、寫程式或建立專案結構。
2. **一次一問**：一次只丟一個問題，等使用者回答後才問下一題。一次問多題會讓人資訊過載。
3. **事實自己查，決策才問人**：凡是能靠環境（檔案系統、工具、程式碼、git log）查得到的**事實**，自己去查，不要問使用者。只有**決策**（有取捨、沒有唯一正解的）才丟給使用者拍板。
4. **每題附上你的推薦答案**：問題不要空著丟出去。走決策樹時，對每個分支都先給出「我建議 X，因為 Y」，讓使用者是在校正你，而不是從零想。

## 執行流程 (Process)

1. **理解意圖**：先收斂核心問題——使用者到底想解決什麼、動機為何、最終使用者是誰。
2. **走決策樹**：把設計拆成一連串相依的決策，逐一往下走。先解掉上游決策（會影響下游的），再處理被它決定的分支。每個決策都：陳述選項 → 給推薦 → 等使用者確認。
3. **用具體情境壓力測試**：當概念之間的關係還模糊時，主動發明具體的邊界情境（edge case）逼使用者講清楚，例如「如果這檔股票當天沒成交量，這個指標要回傳什麼？」
4. **制定規範**：決策樹走完後，把定案的關鍵功能、資料結構、介面邏輯寫下來。
5. **獲取批准**：總結最終方案，明確詢問：『這個設計方案可以開始規劃實作了嗎？』在得到肯定前，不進入實作。

## 輸出要求

- 全程使用「繁體中文」與使用者溝通。
- 寧可多拷問一輪，也不要帶著誤解去實作。
