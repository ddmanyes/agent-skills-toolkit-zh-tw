# 設計腦力激盪
將模糊意圖收斂成可執行的規格。使用者已提供的決策和批准持續有效。

1. 先從需求與適用文件確認目標、讀者、限制與成功條件。可由檔案、工具、程式碼或 Git 查到的事實自行查證。
2. 只提出會實質改變結果的未決問題。相依決策一次問一題；每題附推薦選項及取捨。已有答案不重問。
3. 關係仍模糊時用具體邊界情境檢查，例如資料缺值、空輸入或部分成功，並區分已知限制和待確認假設。
4. 將定案的功能、資料結構、介面、驗收及授權範圍寫成符合任務規模的方案。簡單修改可在對話中說明，跨階段工作沿用專案計畫。
5. 使用者要求先審查，或重要取捨仍未獲決定時，在該邊界等待；已批准且沒有新增重大取捨時，接續授權工作。

完成條件：影響實作的決策已有答案或明確可接受假設，驗收可檢查，未解事項與需要批准的範圍清楚。使用繁體中文；不以固定訪談輪數代替判斷。
